# Решения и открытые вопросы

## 2026-10-01 — этап 1

- Репозиторий пользователя: Stikurt/ALT-Xakaton-TEAM-V, ветка backend.
- Сохраняем стек ТЗ: Python 3.12, FastAPI, psycopg и PostgreSQL. SQLite нет.
- Один процесс Uvicorn; общий цикл состояния будет добавлен на этапе 2.
- Этап 1 содержит только API чтения и начальное сохранение. Нет имитации работы
  чужих модулей. Не выдаём статический moving-пример за реальное исполнение.
- Примеры находятся в shared/examples; shared/station.json остаётся владельцу В.
- GET /api/state имеет явную обёртку snapshot/topology/schema_version.
- Bootstrap повторяемый и не сбрасывает существующий запуск. Новый run создаётся
  только при первом заполнении. Миграции выполняются отдельной командой.
- Результаты команд предусмотрены таблицей commands. HTTP-идемпотентность пока
  не реализована; одна таблица сама по себе её не обеспечивает.
- Для первого локального этапа чтение открыто. Сессии и роли — этап 6; до него
  публиковать сервер в интернет не предполагается.
- Зависимости фиксируются в requirements*.txt; генератор схем повторяемый.

## Учтён уже существующий модуль В

Прочитаны engine.py, station.json и docs/simulation/integration.md из ветки
feat/simulation, commit d4d2b62871ba797b81b86ce08f8114ea51c6ce79.
Координаты теперь пары [x,y], маневры — shunt_to_cargo/shunt_to_storage/
shunt_to_departure, сбой — locomotive_unavailable. Snapshot принимает schema_version
и conflicts. Идентификаторы операций T01 соответствуют модулю В.
State движка непрозрачен для API: snapshot не содержит всей очереди и резервов.
Движок предварительно назначает seq/event_id/state_version; И сохраняет их без
повторной нумерации и только после commit устанавливает transition.state.
Постоянный checkpoint для перезапуска пока требует отдельного согласования.
Текущее ожидание движка имеет wait_reason={code,message}, конфликт end_s=null.
Контракты принимают такой открытый конфликт; завершённые интервалы остаются
полуоткрытыми с положительной длиной.

## 2026-10-01 — этап 2

- Подключены участники В/Н из integration/planner-simulation d44bfb8.
- Запуск по умолчанию: one_train.json. Текущее ограничение полного сценария
  явно описано в upstream-validation.md; состояние infeasible не обходится.
- Bootstrap вычисляет настоящий начальный план в отдельном процессе до записи БД.
- Один управляющий цикл обрабатывает часы и команды; только commit делает новый
  State видимым. PostgreSQL advisory lock предотвращает второго владельца.
- Полный внутренний State хранится в JSON checkpoint, не в pickle. После
  перезапуска восстановление идёт с паузой; исторические snapshots сохранены отдельно.
- При reset восстанавливается тот же исходный сценарий и его рассчитанный план
  с новым plan_id/run_id и повторной проверкой RULES. Старый run архивируется.
- HTTP-идемпотентность хранится в commands вместе с эффектом одной транзакции.
- WebSocket пока без сессий; Origin проверяется, сервер локальный. Авторизация
  и роли остаются отдельным шагом 6, подходящим для параллельной разработки.
- Небольшая правка будущей цепочки в валидаторе Н нужна для resume; описание и
  регрессионные проверки находятся в upstream-validation.md/tests/test_runtime.py.
