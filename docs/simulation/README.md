# Участник В — движок «Узел 12»

Реализация разделов 2–4 и 9 ТЗ «Цифровая станция», версия 1.0 от 01.10.2026.
Ветка: `feat/simulation`. Код рассчитан на Python 3.12, использует только стандартную библиотеку.

## Что готово

- 12 путей, 64 направленных маршрута, независимые горловины GW/GE.
- 15 поездов, 80 операций, пассажирские, транзитные и местные цепочки.
- Дискретная очередь событий; завершение → сбой/восстановление → прибытие → начало операции.
- Пауза, скорости 1/5/10, дробные реальные тики и целые модельные секунды.
- Захват маршрута, ресурсов и целевого пути до начала движения; удержание исходного пути до завершения.
- Занятость станционного пути сохраняется между операциями.
- Общий валидатор вызывается перед каждым началом; ошибки не приводят к перемещению.
- Принятие нового плана сохраняет факты и уже запущенные завершения.
- Опоздание scheduled-поезда, закрытие пути, недоступность свободного локомотива.
- Атомарный пакет сбоев, один признак запроса пересчёта на пакет.
- Идемпотентные команды, новый run_id после reset.
- Функции возвращают новое состояние и события; SQL и WebSocket здесь отсутствуют по ТЗ.

## Проверить на Windows

Если проект ещё не скачан, откройте терминал VS Code и выполните:

```powershell
git clone https://github.com/Stikurt/ALT-Xakaton-TEAM-V.git
cd ALT-Xakaton-TEAM-V
git switch feat/simulation
py -3.12 -m unittest discover -s tests/simulation -v
py -3.12 tests/simulation/run_scenarios.py
```

Если уже скачан:

```powershell
git fetch origin
git switch feat/simulation
git pull --ff-only
py -3.12 -m unittest discover -s tests/simulation -v
py -3.12 tests/simulation/run_scenarios.py
```

Если `py` недоступен, используйте `python`, предварительно проверив `python --version`.
В Linux/macOS команды проверки те же с `python` вместо `py -3.12`.
Пакеты через pip для этих проверок не нужны. Тесты `unittest` можно позднее включить в общий запуск pytest участника И.

Ожидается: 38 успешных тестов. Демонстрационный прогон печатает 15 отправленных поездов,
80 завершённых операций, последнее отправление в 6720 с, 0 событий ожидания на фиксированном плане.
Это **консольная проверка исполнения**, интерфейс приложения ещё не подключён.

## Что ещё нужно для общего приложения

Участник И подключает общие Pydantic-модели, последовательный управляющий цикл,
транзакции PostgreSQL и публикацию WebSocket. Участник Н подключает `can_start` и
`validate_plan`, рассчитывает новые назначения и метрики. Участник Р получает `movement`
и геометрию маршрута для анимации. Участник К подключает управление и панели.

Без объекта `rules` принятие плана и выполнение не разрешены. `PermissiveRules` находится
только в тестах и нужен для изолированной проверки исполнения. **Не импортировать его в backend.**
Фиксированный JSON-план — вход регрессионного теста, а не работающий планировщик и не
сертификат допустимости от Н. Перед включением в общую сборку его проверяет настоящий валидатор.

Реализация не претендует на готовность всего продукта или выполнение приёмки всей команды:
совместной сборки, PostgreSQL, UI, истории, индекса и нагрузочных измерений пока нет.
